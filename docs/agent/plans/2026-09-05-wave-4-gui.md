# Wave 4: the desktop application — Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox
> (`- [ ]`) syntax for tracking.

**Goal:** A Dear ImGui application under `sushihub/gui/` that spawns `ss --json <command>`, reads
the event stream, and gives every `ss` command a screen: five drawn by hand, the rest generated
from `ss --describe`.

**Architecture:** Four layers, each a directory, each depending only on the one below.
`bridge/` spawns a process and turns its stdout into a thread-safe queue of lines; it knows
nothing of JSON. `contract/` parses one line into an `Event` and the catalogue into `Command`
records against the schemas in `sushihub/contract/`; it knows nothing of processes or pixels.
`model/` runs a command through the bridge and folds its events into a `RunState` the UI reads
each frame; it knows nothing of ImGui. `ui/` draws: a shell with a sidebar, five hand-drawn screens,
one `GeneratedForm` that renders any `Command`. `main.cpp` wires them. Tests cover `bridge`,
`contract` and `model` with GoogleTest; `ui` is checked by running the application.

**Tech Stack:** C++17, CMake ≥ 3.25 with presets, vcpkg manifest mode: `imgui[glfw-binding,
opengl3-binding]`, `glfw3`, `nlohmann-json`, `gtest`. Coding style: sushiruntime's
`docs/CONTRIBUTING.md` §4 (Allman braces, `snake_case` functions, trailing-underscore members,
full names, no abbreviations).

**Spec:** `docs/agent/specs/2026-09-05-hub-design.md` §7, §8.

### Task 1: Project skeleton and an empty window

**Files:** `CMakeLists.txt`, `CMakePresets.json`, `vcpkg.json`, `README.md`, `src/main.cpp`,
`src/ui/Shell.hpp/.cpp`, `src/ui/Theme.hpp/.cpp`, `tests/CMakeLists.txt` (empty test target).

`main.cpp` creates a GLFW window titled "SushiStack", an ImGui context with the OpenGL3 backend,
runs the frame loop calling `Shell::draw()`, exits cleanly. `Shell::draw()` draws a left sidebar
with the five screen names and an empty right pane. `Theme` sets a dark palette and 6 px rounding.

Agent check: `clang++ -std=c++17 -fsyntax-only -I<vcpkg include> src/main.cpp src/ui/*.cpp`.
User build: `cmake --preset windows-x64 && cmake --build --preset windows-x64` from `sushihub/gui`.
Acceptance: the window opens and closes.

Commit: `feat(gui): open a window with the five screens named`.

### Task 2: `bridge/`

**Files:** `src/bridge/LineQueue.*`, `src/bridge/Process.*`, `tests/bridge_test.cpp`.

**Interfaces:**
```cpp
class LineQueue { void push(std::string); bool try_pop(std::string&); void close(); bool closed() const; };
class Process {
public:
    static std::unique_ptr<Process> start(const std::vector<std::string>& argv, LineQueue& out);  // nullptr on spawn failure
    void write_line(std::string_view line);   // to child stdin, newline appended
    bool running() const;
    int  exit_code();                          // blocks; also closes the queue
};
```
Windows through `CreateProcessW` with pipes, POSIX through `posix_spawn`; a reader thread pushes
complete lines. Tests: two lines and exit 0 from a Python one-liner; a line written to stdin comes
back from `python -c "import sys;print(sys.stdin.readline().strip())"`.

User build: `cmake --build --preset windows-x64 && ctest --preset windows-x64 -R bridge`.

Commit: `feat(gui): spawn a process and read its stdout line by line`.

### Task 3: `contract/`

**Files:** `src/contract/Event.*`, `src/contract/Catalogue.*`, `tests/event_test.cpp`,
`tests/catalogue_test.cpp`, `tests/fixtures/`.

**Interfaces:**
```cpp
struct LineEvent { std::string level, message; };  struct CommandEvent { std::string command; };
struct HeaderEvent { std::string title; };          struct PanelEvent { std::string title, body; };
struct TableEvent { std::string title; std::vector<std::string> columns; std::vector<std::vector<std::string>> rows; };
struct ProgressEvent { std::string label; int index, count; std::optional<double> fraction; };
struct ResultEvent { bool ok; nlohmann::json payload; };
struct PromptEvent { std::string id, message; std::optional<std::string> default_answer; };
using Event = std::variant<LineEvent, CommandEvent, HeaderEvent, PanelEvent, TableEvent, ProgressEvent, ResultEvent, PromptEvent>;
struct ParseError { std::string reason; };
std::variant<Event, ParseError> parse_event(std::string_view line);

enum class ParameterType { string, boolean, integer, number, path, choice };
struct Parameter { std::string name, help; bool is_argument, multiple, required; ParameterType type;
                   nlohmann::json default_value; std::vector<std::string> choices, flags; };
struct Command { std::string name, help; std::vector<Parameter> parameters; std::vector<std::string> applies_to; };
struct Catalogue { std::string program, version, contract; std::vector<Command> commands; };
std::variant<Catalogue, ParseError> parse_catalogue(std::string_view json);
```
Fixtures are real output the user records: `ss --json status > tests/fixtures/events/status.jsonl`,
`ss --describe > tests/fixtures/describe.json`. The agent writes the tests against the schema's
key names and asks for the fixtures in the report.

Commit: `feat(gui): parse the event stream and the catalogue`.

### Task 4: `model/`

**Files:** `src/model/RunState.hpp`, `src/model/CommandRun.*`, `src/model/Workspace.*`,
`tests/model_test.cpp`.

**Interfaces:**
```cpp
struct RunState { std::vector<LineEvent> lines; std::vector<TableEvent> tables; std::optional<ProgressEvent> progress;
                  std::optional<PromptEvent> pending_prompt; std::optional<ResultEvent> result; std::vector<ParseError> errors; bool finished; };
class CommandRun {
public:
    CommandRun(std::vector<std::string> ss_argv);        // e.g. {"ss","--json","status"}
    bool start();
    void poll();                                          // drain the queue, fold into state()
    void answer_prompt(std::string_view answer);          // writes to stdin, clears pending_prompt
    const RunState& state() const;
};
class Workspace {                                         // one CommandRun per screen, refreshed on demand
public:
    explicit Workspace(std::string ss_executable);
    CommandRun& run_for(std::string_view screen);         // "status" -> ss --json status, etc.
    void refresh(std::string_view screen);
};
```
`model_test.cpp` builds a `CommandRun` over a scripted `LineQueue` (constructor overload taking a
queue, for tests) and asserts the fold.

Commit: `feat(gui): fold a command's events into a state the UI reads each frame`.

### Task 5: Widgets, the Status screen, and the generated form

**Files:** `src/ui/widgets/*`, `src/ui/screens/StatusScreen.*`, `src/ui/forms/GeneratedForm.*`,
`Shell` routes to them.

`StatusScreen` shows the `table` events from `ss --json status` through `TableView`, the result
payload's dependency line, a Refresh button. `GeneratedForm` takes a `Command`: each `Parameter` a
widget by type (checkbox, input text, input int, combo for choice, path with a Browse button that
uses ImGui's text input only), a Run button that assembles argv (`--flag` for true booleans,
`--opt value` for others, positionals in order) and starts a `CommandRun`, an `EventLog` below,
`ProgressBar` from `progress`, `PromptDialog` when `pending_prompt` is set. The sidebar lists the
five screens and then every catalogue command not covered by a screen.

User build and run; acceptance: `status` renders; `ss home` runs from a generated form and its
result payload is shown.

Commit: `feat(gui): draw the status screen and a form for every other command`.

### Task 6: The other four screens

# Wave 0, Task 5: the `sushicore` injection — steps 1 to 3

**Plan:** `docs/agent/plans/2026-09-21-wave-0-uncovered-seams.md`, Task 5.

## What was done

Created `sushihub/cli/tests/test_cli_install.py`, pinning today's behaviour of
`sushistack.services.modules._install_module_cli`, `sushicore_dir` and `_cli_package_name`:

- `sushicore_dir` resolves the fixed `<root>/sushicore` path and returns `None` when its
  `pyproject.toml` is missing.
- A checkout without `cli/pyproject.toml` is skipped without ever calling `_pipx_cmd`.
- A missing pipx is reported and the install fails, naming the command to run by hand.
- A missing `sushicore` is reported after the pipx install runs, and no inject follows.
- The happy path installs the module's `cli/` with pipx, then injects `sushicore` as an
  editable distribution into the package `_cli_package_name` names.

The plan's test module was read against the real `sushihub/cli/sushistack/services/modules.py`
before it was written. Every assertion in the plan (the two warning messages, the pipx command
shapes, the return values) matched the code exactly — **no assertion needed correcting.** The
file was written and run as given, verbatim except for the docstrings noted below.

Two changes from the plan's literal text, both required by the task brief rather than by a
wrong assertion:

- Rewrote the six `test_*` docstrings so each starts with its verb (`python-code-style` /
  `source-comments`), e.g. `"sushicore_dir resolves to..."` became `"Resolves sushicore
  to..."`. The plan's wording was semantically correct; only the grammatical shape changed.
- No other line of the plan's test code was altered.

Both stand-ins were verified to actually intercept, not merely assume interception:
- `test_a_module_without_a_cli_package_is_skipped` sets `_pipx_cmd` to a lambda that calls
  `pytest.fail(...)`; the test passing confirms `_pipx_cmd` was never reached.
- `test_a_missing_sushicore_stops_after_the_install` and
  `test_the_happy_path_installs_then_injects` replace `modules.subprocess` with the `_Runs`
  stand-in and assert on `runs.commands` — the recorded argv lists match the pipx commands the
  code builds, which is only possible if `subprocess.run` was never called.

The `Recorder` console spy was imported from `sushihub/cli/tests/test_presence.py`; no second
spy was written.
